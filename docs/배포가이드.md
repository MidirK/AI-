# 배포 가이드 (무료 티어 기준)

학과 승인을 받은 뒤, 실제로 학생들이 접속할 수 있게 만드는 순서입니다.
계정 생성·환경변수 입력은 직접 진행해야 합니다 (Claude가 대신 로그인/결제할 수 없음).

## 0. 준비물

- GitHub 저장소 (이미 `origin`에 연결되어 있음)
- 이메일 (각 서비스 가입용)

## 1. DB: Neon (Postgres)

1. https://neon.tech 가입 → 새 프로젝트 생성 (리전은 가까운 곳, 예: Asia)
2. 생성된 **Connection string**을 복사 (`postgresql://user:password@host/dbname?sslmode=require`)
3. `postgresql://` → `postgresql+psycopg2://`로 앞부분만 바꿔서 보관해둔다 (SQLAlchemy용).
   → 이 값이 3단계에서 쓸 `DATABASE_URL`

## 2. 백엔드: Render

1. https://render.com 가입 (GitHub 계정으로 로그인하면 연동이 쉬움)
2. New + → Blueprint → 이 GitHub 저장소 선택 → `backend/render.yaml`을 자동 인식
3. Environment 탭에서 값 입력:
   - `DATABASE_URL`: 1번에서 만든 Neon 연결 문자열 (`+psycopg2` 붙인 버전)
   - `SECRET_KEY`: 아래 명령으로 랜덤 값 생성해서 채운다 (절대 기존 개발용 값 재사용 금지)
     ```
     python -c "import secrets; print(secrets.token_hex(32))"
     ```
   - `CORS_ORIGINS`: 3번에서 만들 Vercel 프론트엔드 주소 (예: `https://aicom.vercel.app`)
   - `ALLOWED_EMAIL_DOMAINS`: 학교 이메일 도메인 (예: `ai.university.ac.kr`). 비워두면 아무 이메일이나 가입 가능하니 운영 환경에서는 반드시 채운다.
4. 배포 완료되면 `https://aicom-backend.onrender.com` 같은 주소가 생긴다. `/api/health`로 접속해 `{"status":"ok"}` 확인.

> Render 무료 플랜은 15분간 요청이 없으면 슬립 상태가 되고, 이후 첫 요청이 30초 정도 걸릴 수 있습니다.
> 학과 규모 트래픽에서는 크게 문제되지 않지만, 신경 쓰인다면 유료 플랜($7/월)으로 올리면 해결됩니다.

## 3. 프론트엔드: Vercel

1. https://vercel.com 가입 (GitHub 계정 연동)
2. New Project → 이 저장소 선택 → **Root Directory를 `frontend`로 지정**
3. Environment Variables에 추가:
   - `VITE_API_BASE_URL`: `https://aicom-backend.onrender.com/api` (2번에서 만든 백엔드 주소 + `/api`)
4. Deploy. 완료되면 `https://아무이름.vercel.app` 주소가 생긴다.
5. 이 주소를 다시 2번의 `CORS_ORIGINS`에 넣고 Render를 재배포한다 (서로의 주소를 알아야 함).

## 4. 도메인 연결 (선택)

- 학과에서 서브도메인을 받을 수 있으면 IT 담당자에게 CNAME을 Vercel로 연결해달라고 요청
- 직접 구매한 도메인이라면 Vercel 프로젝트 → Settings → Domains에서 연결

## 5. 최초 관리자 계정 만들기

1. 배포된 사이트에서 관리자로 쓸 계정으로 먼저 일반 회원가입
2. Render 백엔드 서비스의 Shell(또는 로컬에서 운영 DB에 접속 가능한 환경)에서:
   ```
   python -m scripts.promote_admin 관리자이메일@ai.university.ac.kr
   ```
3. 이제 이 계정으로 로그인하면 공지사항 작성 등 관리자 권한을 쓸 수 있다.

## 6. 법적 문서 채우기

`docs/이용약관.md`, `docs/개인정보처리방침.md`의 `[ ]` 부분을 채우고,
프론트엔드에 링크(예: 푸터)를 추가한다 — 아직 화면에 연결은 안 되어 있으니 별도 요청 시 작업 가능.

## 7. 배포 후 체크리스트

- [ ] `/api/health` 정상 응답
- [ ] 실제 도메인에서 회원가입 → 로그인 → 글쓰기 확인
- [ ] `ALLOWED_EMAIL_DOMAINS` 적용되어 외부 이메일 가입이 막히는지 확인
- [ ] `SECRET_KEY`가 로컬 개발용 값이 아닌 새로 생성한 값인지 확인
- [ ] 관리자 계정 승격 완료
